主要修改

文件：root.go
在 init() 已注册 --log-encoding 持久 flag（之前完成）。
在 loadConfig 中，调用 config.Init(...) 之后，执行：
f := rootCmd.PersistentFlags().Lookup("log-encoding")
vv := config.GetViper()
vv.BindPFlag("log.encoding", f)
这样做使得：如果命令行传入 --log-encoding，viper 会将其作为 log.encoding 的值（并自动拥有更高优先级）。

提示

BindPFlag 已确保命令行值会覆盖配置文件和环境。若你希望同时支持环境变量（MYAPP_LOG_ENCODING），viper 已通过 AutomaticEnv 启用环境变量读取；优先级：flag > env > config file > defaults。
我没有添加值校验（例如只允许 json 或 console）。如果希望在解析 flags 时立即校验并返回友好错误，我可以在 rootCmd 的 PersistentPreRun 或在 loadConfig 后添加一段简单的验证。

$env:SERVER_ID = "srv-01"
go run main.go serve --log-encoding console
========================================================
本地运行（Linux / macOS bash）
export SERVER_ID=srv-01
go run main.go serve --log-encoding console
========================================================
在 docker run 中指定运行时环境（即时注入）
这会把 SERVER_ID 注入容器环境，程序通过 viper.BindEnv("server.id","SERVER_ID") 可读取：
docker run --rm -e SERVER_ID=srv-01 -p 8080:8080 viper2:latest serve --log-encoding json
========================================================
在构建时以 build-arg 嵌入（写入镜像 LABEL / ENV）
如果想把 id 编译/打包进镜像（镜像 metadata），可在 build 时传入：
docker build --build-arg VERSION=1.2.3 --build-arg SERVER_ID=srv-01 -t viper2:1.2.3 .
# 运行时仍然可以通过 env 覆盖：
docker run --rm -e SERVER_ID=runtime-01 -p 8080:8080 viper2:1.2.3 serve
========================================================
查看镜像 label（build 时写入的 server.id）：
docker image inspect viper2:1.2.3 --format '{{index .Config.Labels "server.id"}}'
========================================================
docker-compose 示例（在 repo 已有的 docker-compose.yml 基础）
在宿主设置环境变量再启动：
PowerShell:

$env:SERVER_ID = 'prod-01'
docker compose up --build

bash:
export SERVER_ID=prod-01
docker compose up --build
或在 .env 文件或 docker-compose.override.yml 中定义 SERVER_ID。

========================================================
生成 server id 的建议
若希望每台机器自动生成唯一 id，可以考虑：
使用主机名： hostname / Get-ComputerName() （易懂但可能重复）
使用机器唯一 id：Linux /etc/machine-id，Windows 可用 WMI UUID
使用 UUID：uuidgen / 程序内生成并持久化到文件
示例：把宿主 hostname 注入 docker-compose（bash）：

export SERVER_ID=$(hostname)
docker compose up --build
========================================================
安全与治理注意
若 server.id 会暴露到日志/监控，请避免把敏感信息（比如包含机密的路径或 token）作为 id。
若使用 CI 动态注入，请在 CI 中注入短、安全的标识（例如环境名+序号）。
